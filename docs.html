00Overview

Takoraa is the optimization and observability layer for AI applications. You point your existing SDK at the Takoraa gateway, and from that moment every model request can be routed, cached, pruned, measured, and governed — without rewriting your application logic.

The rest of this documentation is organized around three jobs: integrating the gateway into your backend, operating the dashboard day to day, and debugging when something behaves unexpectedly.

01Start here

Takoraa is an optimization layer for AI applications.

Your application sends AI requests to Takoraa instead of calling providers directly. Takoraa then forwards those requests to the appropriate provider, applies enabled optimization rules, records request metadata, and surfaces performance and spend data in the dashboard.

Use Takoraa to

  • Reduce AI spend through routing, caching, and context pruning.
  • Monitor request traffic across clients and app keys.
  • Manage provider access without exposing provider secrets to every integration.
  • Compare estimated baseline cost against optimized usage.
  • Control optimization behavior per customer or per app key.
Adopt gradually. A client can start with a single app key, route a small amount of traffic, review results in the dashboard, and expand only after the pilot is stable.

02Quickstart

Use this guide to connect a backend application to Takoraa.

Before you begin

You need
  • A Takoraa app key.
  • A backend environment where secrets can be stored safely.
  • At least one tested provider connection.
  • Access to the Takoraa dashboard.
Never expose app keys in the browser. Do not place Takoraa app keys in frontend code. Use them only from a trusted backend service.

Integration steps

  1. Set the Takoraa API URL in your backend configuration.
  2. Store the Takoraa app key as a server-side secret.
  3. Send AI requests to Takoraa instead of calling the provider directly.
  4. Include the Takoraa app key with each request.
  5. Confirm the request appears in the dashboard.
  6. Review the route decision, token usage, latency, and estimated cost.
  7. Adjust optimization controls only after the first request path is verified.
src/llm.ts 
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://gateway.takoraa.ai/v1",  // point at Takoraa
  apiKey: process.env.TAKORAA_KEY,           // server-side secret
});

const res = await client.chat.completions.create({
  model: "takoraa/auto",    // routed per request
  messages: prompt,
});

First success criteria

The integration is working when:

Checklist
  • Requests return successfully from Takoraa.
  • Traffic appears in the Requests view.
  • The app key is active.
  • The provider connection is ready.
  • Estimated spend and optimization metadata appear in reports.
  • The client application no longer calls the provider directly for that workflow.

Recommended first pilot

Start with one controlled workflow. Choose a request path that is frequent enough to measure, but not so critical that a configuration mistake affects core production behavior.

Keep optimization conservative at first. Confirm reliability, observability, and billing attribution before expanding.

03Integration guides

Use these guides when adapting an existing AI application to Takoraa.

Migrating from direct provider calls

Replace direct provider calls with Takoraa calls from your backend. Keep provider secrets managed inside Takoraa or your secure server environment. The application should treat Takoraa as the AI gateway for the selected workflow.

Backend integration

Takoraa app keys must be used from backend services only. Store keys in environment variables or a secure secrets manager. Rotate keys when changing environments, handing off ownership, or ending a pilot.

Model routing

Takoraa can route requests based on configured optimization rules. Auto-routing is useful when the application cares about quality, cost, and reliability but does not need to manually select the final provider model for every request.

Streaming

Streaming should be enabled only after the basic non-streaming request path is verified. Confirm that client timeouts, partial responses, and retries behave correctly before using streaming in production.

Tool calling

Tool calling requires stricter validation. Review tool schemas, response shape, and fallback behavior before enabling aggressive optimization on tool-heavy workflows.

Structured outputs

Structured output workflows should prioritize correctness. Use conservative controls until output validity is stable across the selected provider routes.

04Production rollout

Production rollout should happen gradually. Start with one workflow, one app key, and clear monitoring. Expand after request success rate, latency, spend, and fallback behavior are understood.

Expand on evidence, not optimism. Treat each expansion as its own small pilot: widen traffic only once the previous step's success rate and spend have held steady across a representative window.

05Dashboard guide

The Takoraa dashboard is where operators manage clients, keys, provider access, controls, traffic, and reports.

Dashboard
Shows estimated spend, request activity, token usage, model routes, and optimization impact. Use it to understand whether Takoraa is reducing cost without harming reliability.
Requests
Shows recent AI traffic. Inspect request timing, model routing, cache reuse, pruning behavior, provider calls, token usage, and estimated cost impact.
Controls
Manages optimization behavior at the customer level or app-key level. Use defaults for broad behavior and key-level overrides for specific workflows.
API keys
Manages Takoraa app keys used by client backends. Keys can be created, renamed, assigned provider access, made default, revoked, or inspected for spend.
Provider connections
Manages access to providers such as OpenAI and Anthropic. Test a connection before app keys use it — failed or untested credentials should not receive production traffic.
Reports
Summarizes spend, request volume, token usage, and optimization performance over time. Use it to evaluate whether the pilot is ready to expand.
Owner dashboard
Used to create and manage customer profiles. It should be restricted to trusted operators.

06Optimization controls

Takoraa optimization controls determine how aggressively traffic is optimized.

Routing

Routing

Sends eligible requests to efficient provider models based on configured behavior. Useful when the application can accept equivalent responses from different model tiers.

Cache

Response cache

Reuses matching responses for repeated or highly similar requests. Most useful for repeated prompts, support flows, internal tools, and predictable workloads.

Pruning

Context pruning

Removes low-value conversation history before provider calls. Useful for long conversations where older context increases cost without improving the answer.

Quality

Quality judge

Reviews suspicious responses before they are returned. Reduces risk when optimization changes the request path or removes context.

Recommended control strategy

Use conservative settings for the first production pilot. Increase optimization only after monitoring request quality, support tickets, failed requests, latency, and spend data.

07API reference

The Takoraa API is used by backend applications to send runtime AI traffic.

Authentication

Runtime requests require a Takoraa app key. The key must be sent from a backend service and must never be exposed in browser or mobile client code.

Runtime endpoint

POST /v1/chat/completions

Use this endpoint to send chat completion requests through Takoraa.

Required headers

Content-TypeRequired
Must be application/json for chat completion requests.
X-API-KeyRequired
Your Takoraa app key, sent from a trusted backend service. Never expose this in client code.
request.sh 
curl https://gateway.takoraa.ai/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $TAKORAA_KEY" \
  -d '{
    "model": "takoraa/auto",
    "messages": [
      { "role": "user", "content": "Summarize Q3 earnings" }
    ]
  }'

Request behavior

Takoraa receives the request, validates the app key, applies the relevant controls, selects the provider route, forwards the request, records metadata, and returns the provider response.

Response behavior

Responses preserve the expected chat completion behavior while adding Takoraa-side observability in the dashboard.

Errors

Takoraa returns errors when:

  • Authentication fails.
  • The app key is inactive.
  • The provider is unavailable.
  • The request is invalid.
  • The selected route cannot complete successfully.

08Security

Takoraa security depends on correct key handling.

App keys
Used by client backends to send runtime traffic. Store them as server-side secrets and rotate them when access changes.
Admin keys
Used to access the customer dashboard. They should not be used for runtime API calls.
Provider keys
Allow Takoraa to call or sync with external AI providers. Handle provider secrets carefully and add them only in the appropriate provider connection flow.

Key rules

  • Never expose app keys in frontend code.
  • Never paste provider secrets into billing attribution fields.
  • Revoke keys that are no longer in use.
  • Use separate keys for sandbox and production.
  • Keep provider access limited to the workflows that need it.
  • Review request logs before expanding a pilot.

09Troubleshooting

Use this section to resolve common setup and runtime issues.

!Requests are not appearing
The application may still be calling the provider directly, the wrong backend URL may be configured, or the app key may not be included in the request.
!Authentication fails
The app key may be missing, inactive, revoked, copied incorrectly, or from the wrong environment.
!Provider needs test
The provider credential exists but has not passed validation. Test the provider connection before assigning it to production app keys.
!Provider failed
The provider credential may be invalid, revoked, expired, rate-limited, or missing required permissions.
!Spend sync missing
Runtime traffic may still work, but billing or admin access is not connected. Add or validate the provider billing/admin connection to sync real spend.
!No estimated spend
Spend may not appear until requests pass through enabled optimization controls. Confirm that routing, cache, or pruning is active for the relevant customer or app key.
!Unexpected model route
The active controls may allow Takoraa to choose a different route. Review routing settings at both customer level and app-key level.
!Production traffic fails after key rotation
The client backend may still be using the old key. Update the server-side secret and redeploy the backend.
